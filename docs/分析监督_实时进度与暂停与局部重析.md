# 分析监督（HITL on running analysis）：实时进度 · 安全边界暂停 · 局部重析

> 与"复核决策台"（对**结果**复核）互补。这里解决的是对**运行过程**的监督：随时看到分析到哪、随时打断、改要求后只重跑某一部分。
> 实施状态：已完成。全量测试 118 passed；`ruff check app ui tests` 通过。

## 一、三个能力的落点

| 你要的 | 行为 | 关键实现 |
|---|---|---|
| 随时看到分析到哪 | 分析中/暂停/完成后都显示按论文分组的阶段看板（图表观察、四大部分、概述、自动复核、生成报告），逐项 ✓/⏳/○/✗，图表带 done/total | 新表 `analysis_progress`（每 (project,paper,stage) 一行）；`DocumentAnalysisPipeline` 每图、`PaperAnalyst` 各阶段、合成前后落盘；`workspace` 载荷新增 `analysis_board`，UI 3s 轮询渲染 |
| 随时打断（可续跑） | 任意时刻点「暂停分析」→ 在**安全边界**（当前图表/当前专家块结束后）停下 → 阶段变 `paused`，中间产物全保留 → 点「继续分析」从停点续跑，已完成的不重算 | `projects.pause_requested` 协作标志；worker/流水线在每张图前、每个部分前、论文间、生成报告前检查，抛 `AnalysisPausedError` → 优雅置 `waiting/analysis_paused` 且任务不算失败；断点零重算：work_items 按 input_hash 幂等、已完成图表靠 `visual_regions` 键跳过（不会重付视觉调用） |
| 加要求重新分析某一部分 | 暂停后或报告完成后：选论文 → 选「问题与贡献 / 方法与机制 / 实验与结果 / 局限与相关性 / 概述」→ 填补充要求 → 提交；只重跑该块（其余部分走 work_items 缓存零成本），完成后自动重生成最终报告 | 新表 `analysis_part_instructions`（每 (revision,paper,part) 存要求，注入对应块的 prompt → input_hash 变化自动失效缓存）；动作只删该 (paper,part) 的缓存行与该论文的分析行；合成阶段重新执行 |

## 二、新增动作（复用现有 actions 端点）

- `pause_analysis` — 置暂停标志，等待当前边界落下。
- `resume_analysis` — 清标志，从 `analysis_paused` 恢复入队（已完成部分零重算）。
- `reanalyze_part {paper_token, part, instruction?}` — 保存该部分补充要求 → 清该块缓存 → 删该论文分析行与报告 → 入队；其余论文/部分不动。

## 四、验证方式

自动化：
```powershell
python -m pytest tests/unit/db/test_analysis_supervision.py tests/unit/test_review_desk.py -q
python -m pytest tests -q
```
手工（需要真实 Ollama 跑分析）：
1. 分析进行中：页面在进度条下方显示分篇看板；点「暂停分析」→ 状态变"分析已暂停"（等待当前图表/块结束），看板不再有 ⏳。
2. 点「继续分析」→ 从停点续跑；观察 traces（`analysis_paused`/`analysis_resumed`）与"已完成项不重复"。
3. 完成后再进「综合分析」→ 「重新分析某一部分」→ 选论文+方法块+填要求 → 提交 → 观察只重跑该方法块（其余块走缓存），随后报告重新生成且方法部分按新要求改写。
4. 想快速看到暂停效果：可在 `.env` 设 `VISUAL_ANALYSIS_CONCURRENCY=1` 并在分析图表阶段点暂停，验证"当前图表完成后停下"。

> 说明：暂停请求在"当前图表/当前分析块"结束后生效（不硬切单次 LLM 调用），这是零重算续跑的前提；跨论文/跨块边界的暂停即刻生效。
